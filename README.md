# SurfCore for Codex 0.1.8.2

> **鸣谢**　感谢原版 [SurfCore](https://github.com/Mieksido/surfcore) 的作者 [Mieksido](https://github.com/Mieksido) 和所有贡献者。

这个本地原型借鉴 SurfCore 的角色包设计。每个角色有自己的 `persona.md`、共享手记和分会话记录。内置「林」和「明」，也可用自己的 Markdown 人设卡新建角色。切回已有角色会重新读入它自己的近期记录。

QQ 私聊和模拟消息分别保存在角色目录下。最近 30 天内最多 10 轮对话会提供给模型，其余留在本地存档。用户明确保存的手记可以在 Codex 和 QQ 共用，QQ 原始会话记录不会通过插件工具暴露给 Codex 桌面聊天。角色状态默认在 `%LOCALAPPDATA%\SurfCoreCodex`，可用 `SURFCORE_DATA_DIR` 指定目录。

## 在 Codex 中使用

需要 Node.js 24 和当前的 Codex CLI。在本目录执行下面两条命令，随后打开新的 Codex 对话。

```powershell
codex plugin marketplace add .
codex plugin add surfcore-codex@surfcore-local
```

也可以从桌面端的插件目录选择 **SurfCore Local**，安装 **SurfCore for Codex**。在新对话里可以说：

- 用 SurfCore 列出角色，然后切到明。
- 新建角色「白露」，ID 用 `bailu`。人设卡如下……
- 切到白露，记住我喜欢雨天的白噪声。

## 本地模拟

在本目录运行：

```powershell
node plugin/src/cli.mjs list
node plugin/src/cli.mjs demo '林，记住我爱喝茶'
node plugin/src/cli.mjs activate ming
node plugin/src/cli.mjs demo '明，你记得前一轮吗？'
node plugin/src/cli.mjs activate lin
node plugin/src/cli.mjs demo '回到林'
node plugin/src/cli.mjs probe
node plugin/src/cli.mjs demo-codex '请用一句话向我打招呼'
```

`demo` 用模拟回复检查角色和上下文路由。`probe` 只检查本机 Codex App Server 和 MCP 隔离。`demo-codex` 用本机 Codex 当前登录和模型配置生成回复。QQ 适配只用一次性 Codex 会话，由本地存储提供选出的记忆。

Codex 子进程优先沿用终端已有的代理设置。Windows 开启了本机 HTTP 代理且终端未设置代理时，桥接会把系统代理传给 Codex 的 HTTPS 请求。QQ 的 OneBot 地址仍走本机回环。

## Codex 接入 QQ

控制台的“QQ 桥接”提供“启动 SnowLuma”和“打开 SnowLuma”：在启动控制台前用 SURFCORE_SNOWLUMA_DIR 指定已有的安装目录。启动前检查本地监听地址和关闭自动加载 QQ 的配置；点击启动会等待页面就绪后自动打开，浏览器拦截弹窗时可点击“打开 SnowLuma”。用户需在 SnowLuma 页面手动登录、操作机器人。页面就绪不保证机器人已连接。需要重启 SurfCore 控制台才会加载新版。

1. 按 [SurfCore 原版指南](https://github.com/Mieksido/surfcore/blob/main/docs/guides/INSTALL.md) 的 SnowLuma 部分，启动 SnowLuma 并用机器人 QQ 扫码。在 OneBot v11 配置启用本机的正向 WebSocket 和 HTTP。原版指南里的 DSH 安装步骤属于原版。
2. 在同一个 PowerShell 窗口设置以下参数。机器人号和你用来发私聊的号必须不同。可用 `SURFCORE_QQ_ADMINS` 设置管理员 QQ，用 `SURFCORE_QQ_GROUPS` 设置群白名单。多个号码用逗号分隔。没有设令牌可省略令牌那一行。若 HTTP 和 WebSocket 的令牌不同，用 `SURFCORE_ONEBOT_HTTP_TOKEN` 和 `SURFCORE_ONEBOT_WS_TOKEN` 分开设置。
3. 启动预览。桥接先用 OneBot HTTP 核对当前登录的是配置的机器人号。然后拿主人号发一句文字给机器人号，在终端看生成的回复。确认后按 Ctrl+C 停止，再加 `--send` 重开即可回到真实 QQ。

```powershell
$env:SURFCORE_QQ_OWNER = '你的主号'
$env:SURFCORE_QQ_BOT = '扫码登录的机器人号'
# 可选，允许管理员和机器人私聊
$env:SURFCORE_QQ_ADMINS = '管理员QQ号'
# 可选，逗号分隔的群号
$env:SURFCORE_QQ_GROUPS = '测试群号'
$env:SURFCORE_ONEBOT_TOKEN = Read-Host 'OneBot access token' -MaskInput
$env:SURFCORE_ONEBOT_WS = 'ws://127.0.0.1:3001'
$env:SURFCORE_ONEBOT_HTTP = 'http://127.0.0.1:3000'
node plugin/src/cli.mjs qq
# 看完预览，Ctrl+C 后手动重开
node plugin/src/cli.mjs qq --send
```

端口按 SnowLuma 界面填写。QQ 桥接处理主人或管理员发来的纯文字。主人私聊可以直接回复；发送模式下，启用自主参与后，主人首次正常私聊回复后会询问是否允许本次登录参与白名单群，明确回复“同意群聊”后才参与，回复“撤销群聊”可关闭，退出或重启后授权失效。群消息必须来自白名单群。未启用自主参与时，只有主人或管理员在白名单群内 @ 机器人才会触发回复。私聊按发件人保存，群聊按群保存，两种记录彼此独立。角色的共享手记只用于主人的私聊。预览时会用 Codex 处理收到的文本，预览回复不会发出去或写入正式对话历史。连接断开后重新运行桥接即可。

发送模式下，普通回复不超过 15 个字符时，桥接用角色绑定的音色试合成，成功后由模型选择发语音或文字。超过 15 个字符、合成超过 4 秒或音色不可用时发送文字。模型判断对方明确要求语音时，桥接会尝试合成语音稿，最多尝试两次，共用 8 秒。合成成功就发送语音。合成未完成时，模型可选择沉默或另作回应，原语音稿只用于合成。群聊沿用白名单、本次授权和唤醒规则。同一群里同一个人的连续文字等最后一条停顿 1.5 秒后一起处理，最长等 4 秒。消息原文逐条保存。

模型可以在聊天里选择唱歌，或按点歌请求选段。已有换声片段时按歌词、句数、开头或副歌查本机曲库 `<语音目录>/qq-songs.json`。未指定位置且两段都有时随机选择。

学唱功能收到新歌点播时会先查本机原音源，需要寻找新音源时优先使用 QQ 音乐；客户端不可用时再从 Wikimedia Commons 和 Internet Archive 查找可下载录音。点「前 30 秒」时，从开唱前 1 秒截到约半分钟处的完整句尾，最长 40 秒。缺少开头标记时，自动调用本地 Demucs 分离人声，再用 Whisper 时间戳核对开唱和句尾停顿；已有人工标记时优先使用人工结果。开头证据不足时，优先随机选择有本地人声活动证据、起止靠近停顿的连续约 30 秒片段，中间不要求逐句确认；没有此类候选时，按用户设定在音源内随机截取 30 秒（短音源取全部），此时无法保证起止句子完整。明确点副歌时仍使用这份录音的副歌时间点。用本机配置的分离与 Seed-VC 模型将片段换成学唱音色，混回伴奏后在原会话发送。音源和处理结果缓存在 `<语音目录>/qq-song-learned`。

可以从下载目录后台读取与歌名、歌手唯一匹配的录音以及同名歌词。点歌明确指定版本且下载中只有一个匹配时，也可以在未指定歌手的情况下读取。Windows 版可调用已登录的 QQ 音乐 18.44.0 客户端搜索并选择 HQ 下载。未指定歌手或版本时，使用歌名和「女声」搜索，按搜索结果从上到下直接选择第一首；已知男声录音仍跳过。指定歌手或版本时按指定内容匹配。通过 `SURFCORE_QQ_MUSIC_EXE` 设置客户端可执行文件的绝对路径，把下载目录设为 `<语音目录>/qqmusic`。自动搜索或下载需要 Windows 允许客户端取得前台焦点。程序校验下载音频后入库，并保留原件及同名歌词。新录音的开头可自动定位，副歌需要同版标注。设置环境变量 `SURFCORE_QQ_MUSIC=off` 并重启控制台可关闭 QQ 音乐来源。

搜索选定版本后优先复用该版已入库录音或未变化的完整下载；多歌手下载文件名中的 ` _ ` 与页面歌手分隔逗号按同一名单匹配，不改变成员顺序。正在变化的下载仍需等待稳定，不把其他同名版本当成所选录音。

学唱时并行读取同版 LRC，支持 UTF-8、UTF-16 和 GB18030，按实际演唱片段的原录音秒数取词；已有片段优先使用人工歌词索引。旧导入音源通过音频内容哈希核对同版下载，原歌词另存于 `<语音目录>/qq-song-lyrics`，不修改人工索引。OneBot 回读确认语音条后，歌名、版本、片段和对应歌词写入当前角色、当前会话的演唱记忆。后续角色可据此解释唱了什么及歌词情感；时间轴不等于逐词确认，缺少末句边界、歌词截短和无时间轴资料会保留相应局限。缺词不阻止唱歌，也不凭歌名编造唱词或情感。这项改动不改变换声音频的情绪表现。

开头定位只扫描音源前 100 秒，使用本机已有模型，不联网下载。结果按音源内容和分析程序版本缓存在 `<语音目录>/qq-song-timing`；同一路径替换录音后会重新识别。识别与换声共享模型队列，避免同时占用显存。识别依赖 `<语音目录>` 下的 Demucs 与 Seed-VC Python 环境，以及本机 Whisper base；可用 `SURFCORE_WHISPER_CLI` 和 `SURFCORE_WHISPER_MODEL` 指定 Whisper 程序和 base 模型位置。

点歌和学唱的失败、准备进度及繁忙提示，在群聊和非主人私聊里由当前角色模型根据实际状态生成，不发送底层技术诊断，也不把失败说成成功。主人号私聊保留具体错误和失败阶段，完整诊断仍写入日志。状态回复生成本身不可用时记录异常并使用简短备用文字，不递归尝试点歌。

可在「QQ 桥接 → 学唱音源」导入本机录音并填写开唱、完整句尾和副歌秒数。手动维护曲库时，开唱与句尾记在 `source.opening` 的 `vocalStart` 和 `phraseEnd`，副歌记在 `source.chorus` 的 `start` 和 `end`。语音条提交成功后尝试通过 OneBot 回读，提交结果不明确时日志提示先查看 QQ。

源码支持 QQ 图片、依赖 OneBot `fetch_ptt_text` 的语音转写，以及对短于三分钟的视频抽帧和音轨识别；QQ 原生转写失败时可回退到本地 Whisper。资源获取失败、静音或识别器不可用时会明确标注。QQ 语音发送目前已通过模拟网关验收，接收端播放待实测。视频抽帧和本地识别需要 ffmpeg，可使用 `SURFCORE_FFMPEG` 指定路径。B 站和桌宠尚未移植。

图片慢加载暂答默认开启。私聊和本次已授权的白名单群中，如果图片加载超过 3 秒，模型可先根据文字和上下文暂答。图片就绪后，模型按需要补充或纠正。这个选项在 QQ 桥接设置中可关闭。

发送模式下，模型可按需读取当前会话最近 15 条消息和已核实的引用。群聊读取同时要求群白名单与本次授权。QQ 官方图片链接过期时，桥接可尝试刷新下载凭据，下载中断时会在符合条件的官方地址上续传。

本地表情收藏按机器人账号、角色和会话隔离，所有角色共用 200 MB 原图容量。模型可以给自己的收藏写备注、发送或删除。GIF、APNG 和动态 WebP 以有序画格预览，完整预览后才可收藏。动图预览依赖带 Pillow 的 Python，可用 `SURFCORE_STICKER_PYTHON` 指定解释器。

## 本地控制台

在 Windows 上，点击 Codex 插件详情里的「立即试用」，或双击 `Start-Panel.cmd`，即可在默认浏览器打开控制台。两种方式共用本机后台进程，退出启动命令后控制台仍可使用。需要前台运行时，可用 `node plugin/src/cli.mjs panel`，再复制终端显示的完整地址到浏览器。默认使用系统分配的空闲端口，可用 `SURFCORE_PANEL_PORT` 指定。

- 角色：创建、编辑、激活角色，保存存档或从存档恢复人格。恢复人格时保留后续记忆。
- 记忆：按角色与记录范围检索、分页查看，添加角色手记，强化或取消强化；强化只影响原作用域。召回预览依据实际会话规则。
- 自动提炼：每个群或私聊分别计算压缩后的当日当前摘要字数；桥接成功发送回复后保存的记录达到 10 条立即提炼，不足 10 条按首次聊天后两小时、之后有新内容再每两小时处理。群初始 300 字、上限 1500 字；非主人私聊初始 100 字、上限 500 字；主人私聊摘要不限额，但隐私筛选仍生效。有限额的对话会将当天已有摘要与下一批新记录一起重新压缩，手动和自动提炼执行同一上限。历史摘要及原始记录另行保留，历史版本不再重复计入当前字数或参与共享召回；跨日、超限或来源变化时拒绝提交，新记录仍待处理。一次群回复可以对应多条来信，十条保存记录不等于十条入站消息。
- 概括共享：来源完整、通过隐私筛选且未明确拒绝的普通摘要默认可跨对话使用，不再要求另外生成一份共享文本。明确私密、判断不确定、来源变化、归档、衰减和撤销仍会阻止共享。其他对话的模型可读取通过筛选的概括与有来源依据的 QQ 昵称，模型按当前场合决定如何称呼。原始聊天、群号和 QQ 号不进入跨会话召回。未评估的旧候选不自动放开，筛选仍可能漏判。
- 日记：每个角色在 `日记/日记.txt` 按香港日期保存，每日最多 500 个 Unicode 字符；支持追加、覆盖、删除和按版本拒绝过期窗口覆盖。香港时间每天首次打开控制台时会回看当前角色此前三天的记录，由模型决定当天是否写。额度限制或失败保留重试机会，自动回看保留当天已有内容。日记独立保存。
- 角色与记忆存储：在“角色与人格 → 角色与记忆存储位置”打开目录，或者选择空目录并复制切换。迁移前关闭旧版面板、QQ 桥接和仍在运行的旧版 Codex 角色会话；0.1.6 各进程会读取相同的新位置。原目录保留为迁移时备份，之后不会自动同步；额度、连接等其他设置仍放在原数据目录。支持下载当前已保存的人格卡及筛选后的记忆 JSON，文件下载位置由浏览器设置决定。角色目录的 `persona.md` 可能是初始版本，最新版本请在面板导出。
- 每日额度：按香港日期统计已报告 Token、调用次数及未知用量；可以仅统计或设置每日上限。上限在下一轮开始前检查，单轮可能超出剩余额度。
- 账号额度：读取 Codex 账号短周期与长周期剩余比例，设置剩余阈值并阻止 SurfCore 新调用。无法读取时，启用保护会暂停；它不会解除账号额度，也不能限制其他 Codex 会话。
- 语言：保存角色回复语言，影响后续桥接模型调用。
- 语音：兼容原版 voxd 本地/云端包，新增 Breeze 本机 provider，角色保存具体服务、音色及风格；支持整段 WAV 试听和取消。失败明确回文字，只有启用并绑定的在线备选才可降级；端口、健康与实际合成分开显示。控制台不执行自动下载或编辑云凭据。

### 语音排查

1. voxd 按原版语音包说明安装和配置；Breeze 选择包含 `breeze-server.exe` 的目录、GGUF 模型和本机地址，再保存检测。
2. 缺少文件时补齐安装；端口已监听时先运行自检，避免重复启动。端口监听本身不证明该服务就是语音包。
3. 服务未运行时点击启动，等待模型加载并刷新状态。若本控制台启动的进程退出，页面会显示进程名及退出码；详细错误需要在语音包自己的终端中查看，注意不要公开凭据。
4. 自检通过后，在“语言与语音”选择同一服务、加载音色，输入试听文本并点击试听。Breeze 可选已有音色或明确的未保存设计音色，调整指令、种子和指令强度；不提供无效语速参数。voxd 风格 JSON 按包实际支持的键填写。试听不向 QQ 发送语音。
5. 每段最多 300 字符、5 MiB、60 秒，默认超时 60 秒；单服务一次合成一条。取消和失败会显示明确状态。使用在线备选须先加载并绑定具体云端音色，再勾选允许，保存到该角色；默认关闭，旧二进制试听接口不会偷偷切换服务。

面板地址包含仅用于本机的访问片段。页面会移除地址栏片段；刷新后如需重新认证，请重新打开终端完整链接。控制台不负责启动 QQ 发送。

## 本机依赖和数据

- `SURFCORE_VOICE_ROOT` 指向语音目录，默认为角色数据目录下的 `voice`。在使用学唱前配置自己的分离模型与 Seed-VC 包，并在语音目录提供其所需的脚本、模型与音色档案。
- `SURFCORE_FFMPEG` 可指定 FFmpeg，默认从 PATH 调用 `ffmpeg`。语音和视频转写及开头定位可显式配置 `SURFCORE_WHISPER_CLI` 和 `SURFCORE_WHISPER_MODEL`。读取普通下载音频无需额外转换程序，使用外部转换程序时由 `SURFCORE_QQ_MUSIC_CONVERTER` 指定其路径。
- 下载的自动学唱音源、转换副本、生成音频和符合条件的普通说话临时残留共享 500 MB 缓存预算。超限后等正在使用音频的任务结束再清理。手工入库的录音、训练素材和模型单独保留。
- Git 仓库只需要源码与合成测试。角色数据、日记、记忆导出、QQ 配置、日志、数据库及伴随文件、模型和授权音频应留在本地。控制台完整启动地址的 `#access=` 片段是本地访问凭据。记忆导出可能包含所选范围的原文和账号标识。
- 如果在同一台机器管理多个机器人，请为每个账号设置各自的 `SURFCORE_DATA_DIR`，分别保存角色记忆、桥接配置和恢复状态。
- QQ 回复、记忆提炼及日记回看会把所需上下文提交给配置的 Codex 模型。日记回看使用当前角色保存的近期对话，触发条件是打开控制台。跨会话摘要的来源可在本机面板预览，已撤销和明确私密的条目不会参与跨会话召回。

## 验证

运行 `node --test test/*.test.mjs`。FFmpeg 用例需要 PATH 上的 FFmpeg 或 `SURFCORE_FFMPEG`。可用 `SURFCORE_TEST_PYTHON` 指向已安装音频测试依赖的 Python，以运行混音用例。运行 `python -B test/qq-song-timing-audio.test.py` 可验证时间轴分析。
